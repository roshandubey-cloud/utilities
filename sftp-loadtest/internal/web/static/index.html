Set the track-ID timeout to however long your SFTP server might take to process a file. The tool polls patiently and records the actual processing time once the server renames the file; a file only gets the TRACKID_TIMEOUT error code if it never shows up before this limit. Wall-clock cost: after the upload phase ends, the run keeps draining for up to this much longer to give pending track-IDs time to resolve — a 4 h timeout means the run can stay "active" up to ~4 h past its scheduled end.

Click a suggestion or type your own. Leave blank to reuse the upload folder.
How it works: each download user lists its own folder on every poll tick and pulls every filename it sees ending in #<trackid>. Each download is attributed back to the originating upload row by basename — no pre-configured upload→download mapping is required on the tool side.
Server requirements: for downloads to work, your SFTP server must (a) append a #<trackid> suffix to each processed file, and (b) place the processed file in the download user's folder. Without that server-side routing this card will record zero downloads.
